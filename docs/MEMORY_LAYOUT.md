# 메모리 배치

> English version: [MEMORY_LAYOUT_en.md](MEMORY_LAYOUT_en.md)


## 요약

- 글꼴, 글자 버퍼, 시작 문구, 블리트 변수는 화면 아래 `$0800–$1FFB`에 둔다.
- 화면은 하이레스 1쪽, `$2000–$3FFF`이다. 더 이상 베이직 메모리 한가운데에 있지 않다.
- 베이직은 `$4001–$93FF` 한 덩어리, 21,504바이트이다. `HIMEM`은 `$9400`이고, 프롬프트에서 여유 메모리 21,501바이트가 보인다.
- DOS 3.3은 `$9600`에 둔다. 드라이버는 언어 카드 `$D000–$FFFF`에 있고, 영문 글꼴은 그 안의 `$D860–$E05F`에 있다.
- 이전에는 화면이 2쪽이고 `HIMEM`이 `$7400`이라, 프로그램이 약 14KB에서 막히고 문자열은 5,120바이트 별도 공간이었다. 글꼴, 버퍼, 시작 문구를 1쪽 아래로 옮겨 그 제한을 없앴다.
- `HGR`은 한글 화면을 지운다. `HGR2`는 베이직 프로그램을 지운다. 둘 다 막을 수 없다. 애플소프트 롬에 들어 있는 명령이라 가로챌 램 훅이 없다.


## 각 조각의 위치

| 조각 | 주소 |
|---|---|
| 12×12 글꼴과 시프트 마스크 | `$0800–$1969`, 4,458바이트 |
| 글자 버퍼, 46칸 × 16줄 | `$1980–$1C5F` |
| 줄 플래그 | `$1C60` |
| 블리트 작업 공간 | `$1C80–$1CAF` |
| 롬 벨과 모드 바이트 | `$1CB0–$1CBC` |
| 시작 문구와 프롬프트·CATALOG 도우미 | `$1CC0–$1FCE`, 783바이트 |
| 블리트 변수(마스크, 바이트 수, 줄 번호, 반전 마스크) | `$1FF0–$1FFB`, 12바이트 |
| 화면, 16줄 × 12픽셀 | 하이레스 1쪽, `$2000–$3FFF` |
| 베이직 프로그램, 변수, 문자열 | `$4001–$93FF` |
| 드라이버 스텁과 변수(텍스트 화면 밖이라 `HOME`, `TEXT`, `GR`이 건드리지 못한다) | `$9400–$95FF` (그중 `$95DC` Shift 개조 기준값, `$95DD` 줄 그리기 모드, `$95DE/$95DF` 줄 버퍼 주소, `$95E0/$95E1` 줄 끝 루틴) |
| DOS 3.3 | `$9600` |
| 한글2 드라이버 | 언어 카드, `$D000–$FFFF` |
| 영문 글꼴 (글자 128개 × 16바이트, 10줄 사용) | 언어 카드 `$D860–$E05F`, 2,048바이트 (`FONT6X10` 파일을 `$7200`에 읽은 뒤 `INIT`이 옮김) |

`$7200–$79FF`는 임시 자리일 뿐이라 시작한 뒤에는 BASIC이 써도 됩니다. `$D000–$D0AF`에는 시프트 개조, Ctrl-A, 줄 그리기 루틴(`FIXCONT`부터 `SHREPL`까지)이 있습니다. `$1CBD`는 드라이버 상태 한 바이트로, 애플 IIe, IIc, IIgs 이면 비트 7이 켜집니다(로더가 정합니다). `$D0B0–$D132`에는 `CATFIX`(`CATALOG`의 `]` 고침)와 선택 부가 프로그램 KBASIC용 훅 둘(`KBIN`, `KBOUT`)이 있고, `$D133–$D3FF`(717바이트)는 비어 있습니다. 예전 6×8 영문표는 없어졌습니다. KBASIC을 올리면 주 메모리 `$8A00–$93FF`에 자리 잡고 `HIMEM`을 `$8A00`으로 내립니다(한글 BASIC 프로젝트의 KBASIC 문서 참고).

`$0800–$1FFF`는 6,144바이트이다. 위 조각이 6,051바이트를 쓰고, 93바이트가 남는다.

프롬프트에서 프로그램은 비어 있다. `$4000`은 `0`이고, `TXTTAB`은 `$4001`, `VARTAB`은 `$4003`이다. `HIMEM`은 `$9400`(37888)이다. 시작 문구의 여유 메모리는 `$9400 − VARTAB`이라 **21,501**바이트이다. `$4000`부터 `$93FF`까지 전체는 21,504바이트이다.

원래 한글2는 하이레스 2쪽에 그렸고, 프로그램은 그 페이지 아래 약 14KB, 문자열은 그 위 별도 공간이었다. 화면이 가운데 있지 않으므로 프로그램이 14KB를 넘길 수 있다.

`HGR`은 한글 화면을 지운다. `HGR2`는 베이직 프로그램을 지운다.


## 부팅

`HELLO`는 `FONT12`를 `$6000`에 읽고, 드라이버를 `$0F94`에서 `BRUN`한다. 드라이버는 13,191바이트라 올라오는 동안 `$4000`을 지난다. 초기화는 글꼴을 `$6000`에서 `$0800`으로 복사한 다음 `$4001`에 빈 프로그램을 만든다. 글꼴이 `HELLO`를 덮은 뒤에 20번 줄을 다시 실행하지 않도록, 파서는 그 0바이트를 가리킨다.

`MIXED`와 `STORY`는 자판 입력 텍스트 파일을 `GET`으로 읽어 `PRINT`한다. 이제 `$8000`에는 아무것도 읽지 않는다.


## 이전 빌드

이 이동 전에 같은 드라이버는 화면을 2쪽에 두고 `HIMEM`을 `$7400`으로 두었다. 원래 한글2의 `$9600`보다 8,704바이트 아래였다. 글꼴 4,458바이트(`$7400`), 버퍼와 시작 문구 1,432바이트(`$8C00`), 그리고 `HIMEM` 천장 하나 때문에 닫힌 빈틈 2,814바이트이다. 문자열은 5,120바이트였고 프로그램은 여전히 약 14KB에서 막혔다. 그 조각은 지금 1쪽 아래에 있고, `HIMEM`은 `$9600`이었다. 그 뒤 드라이버 스텁을 텍스트 화면에서 `$9400–$95FF`로 옮겨 지금 `HIMEM`은 `$9400`이다.

드라이버는 언어 카드에 둔다. DOS는 `$9600`에 둔다. DOS를 그 카드에 넣으려면 뱅크가 하나 더 필요하고, 디스크를 부르거나 글자를 찍을 때마다 바꿔야 한다.


## 화면 위에 놓이는 프로그램 (BASIC 메모리 위쪽)

| 프로그램 | 올라가는 주소 | 크기 | 쓰는 곳 |
|---|---|---|---|
| `TYPE` | `$8E00` | 800바이트 | `$8E00-$93FF` (코드, 그다음 섹터 버퍼 `$9200`과 `$9300`). `HIMEM`을 `$8E00`으로 낮춘다 |
| `TYPEC` | `$8E00` | 486바이트 | 같은 자리. 실행하는 동안 덮어쓴다 |
| `STYPE` | `$8A00` | 1,224바이트 | `$8A00-$93FF`: 코드는 `$8EC7`까지, 512바이트 줄 버퍼는 `$90C7`까지, 섹터 버퍼는 `$9200`과 `$9300`. `HIMEM`을 `$8A00`으로 낮춘다. `TYPE`과 자리를 나눠 쓸 수 없다 |
| `STYPEC` | `$8A00` | 951바이트 | `STYPE`과 같은 자리. 실행하는 동안 덮어쓴다 |

줄 버퍼는 `STYPE`이 그리는 글줄의 픽셀 줄 12개로, 줄마다 42바이트이다(`STYPE.md` 참고). 드라이버의 줄 그리기 모드는 `$D000-$D0AF`에 약 200바이트의 코드를 더한다(`LINEX`, `NEXTROW`, `NLHOOK`, `CALLSTRIP`, 그리고 Shift와 Ctrl-A 루틴).
