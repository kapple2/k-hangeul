# DOS 3.3 한글화: 메시지, 명령 이름, 파일 이름

> English: [DOS_KOREAN_REPORT_en.md](DOS_KOREAN_REPORT_en.md)

이 보고서는 검토를 위한 것입니다. DOS 3.3의 어느 부분을 한글로 보여 주거나 받아들일 만한지, 메모리와 작업이 얼마나 드는지, 무엇은 할 수 없는지를 따집니다. **여기 적힌 것은 드라이버나 DOS에 하나도 만들어 넣지 않았습니다.** MAME에서 해 본 것은 세 가지입니다(5.3절): 한글 파일 이름, 그 이름으로 `RUN`과 `BRUN`, 쉼표 문제. 나머지는 DOS 덤프에서 읽었거나 추정이고, 추정이라고 적었습니다.

알아낸 방법: `disk\K-HANGEUL.DSK`의 DOS를 MAME에서 켜고 메모리(`$9600-$BFFF`)를 떠서 `da65`로 읽었습니다. 주소는 그 DOS(이 프로젝트가 `DOS_PATCHES.md`대로 고친 것)의 주소입니다. 메시지 크기는 `src\tools\nbyte.py`로 계산했습니다.

이 보고서는 `DOS_ANALYSIS`, 처음 쓴 `DOS_KOREAN_REPORT`, `DOS_KOREAN_FILENAME_ANALYSIS`를 하나로 합친 것입니다.

## 3. DOS가 무엇을 어디서 찍나

### 3.1 오류 메시지 (14개)

- 글자는 `$A971-$AA3E`(202글자)에 있고, 시작 위치 표가 `$AA3F`에 있습니다. 각 메시지의 마지막 글자만 최고 비트가 켜져 있습니다.
- 메시지 하나를 찍는 루틴이 `$A702`에 있습니다. `X`가 메시지 번호이고, 시작 위치를 읽은 뒤 글자마다 `JSR $9FC5`(DOS의 출력 루틴. 끝에서 드라이버의 출력 훅으로 들어갑니다)로 보내다가 최고 비트가 켜진 글자에서 멈춥니다. 14개 메시지와, 오류마다 먼저 나오는 줄바꿈/종소리가 모두 이 루틴을 지납니다.

### 3.2 `CATALOG` 목록

- 머리글 "DISK VOLUME "은 `$B3A7`에 거꾸로 저장되어 있습니다(같은 표 앞쪽에 파일 종류 글자 8개 `T I A B S R A B`가 있습니다). `$ADB0`의 루틴이 11바이트짜리 반복으로 찍습니다: `LDX #$0B / LDA $B3AF,X / JSR $FDED / DEX / BPL`.
- 그다음: 볼륨 번호(3자리), 그리고 파일마다 잠금 표시 `*`, 종류 글자, 섹터 수(3자리), 30글자 이름.
- 화면을 넘길 때 멈추는 부분(`DOS_PATCHES.md`의 `CATINIT`, `CATWAIT` 고침)은 이미 되어 있습니다.

### 3.3 DOS가 아닌 것

애플소프트 메시지(`?SYNTAX ERROR`, `?OUT OF MEMORY` 등)는 애플 II 롬에 있고 K-BASIC 프로젝트의 몫입니다.


## 4. 한글 오류 메시지와 `CATALOG` 머리글

### 4.1 한글 메시지를 어떻게 찍나

드라이버는 사용자가 치는 것과 같은 키 입력 글(Ctrl-K(`$8B`)로 한글 구간 시작, 자모 키들, Ctrl-A(`$81`)로 끝)을 받으면 이미 한글을 보여 줍니다. 그래서 한글 메시지는 같은 출력 훅으로 다른 글자열을 보내기만 하면 됩니다. 드라이버의 그리기를 고칠 필요는 없습니다. 영어 글을 그 자리에서 덮어쓸 수는 없습니다. 한글 쪽이 더 길기 때문입니다.

계획:
1. DOS는 `$A702`를 불러 메시지 `X`를 찍습니다. 그 루틴의 첫 3바이트를 랭귀지 카드 안의 루틴으로 가는 `JMP`로 고칩니다.
2. 새 루틴이 같은 `JSR $9FC5` 반복으로 한글 메시지를 찍습니다.
3. 한글 드라이버가 출력을 맡고 있지 않으면(`PR#0` 뒤나 Ctrl-Reset 뒤) 새 루틴은 원래 영어 루틴으로 넘깁니다. 한글 글자열이 일반 글자 화면으로 가는 일은 없습니다.

`CATALOG` 머리글도 같은 방법입니다. `$ADB0`의 11바이트 반복을 `디스크 볼륨 `을 찍는 호출로 바꿉니다(같은 대체 동작 포함).

프로그램이 `$9400-$95FF`를 덮어써도(kScheme이 그렇게 합니다) 이 훅이 사라지면 안 됩니다. 이미 쓰는 DOS 고침(`CATINIT`, `CATWAIT`)이 그 블록을 가리키고 `$D3FA`의 재구성 진입점이 그것을 다시 만들어 줍니다. 새 훅도 거기서 다시 만들어져야 합니다.

### 4.4 위험

- 한글 드라이버가 꺼져 있으면 한글은 아무것도 안 되고, 영어 메시지가 나와도 괜찮습니다. 막아야 할 경우는 이것입니다: 드라이버를 올려서 DOS 패치가 들어가 있는데, 그 뒤에 출력이 드라이버에서 다른 곳으로 바뀐 경우(`PR#0`, Ctrl-Reset). 패치는 DOS 안에 그대로 있어서 한글 코드를 일반 글자 화면으로 보내고, 화면에 깨진 글자가 나옵니다. "출력 훅이 드라이버 것인가" 검사가 그때 영어 메시지를 대신 보냅니다. `PR#0`과 Ctrl-Reset 상태에서 시험하세요. 드라이버를 올린 적이 없으면 패치도 없으므로 DOS는 전과 같이 영어로 찍습니다. 영어 명령은 어느 경우에나 됩니다.
- 한글은 영어보다 화면에서 넓습니다. 오류 줄은 짧아서 46열 화면에서 넘칠 일은 없어 보이지만 하나씩 봐야 합니다.
- 메시지마다 시험할 방법이 있어야 합니다. 쉬운 것: FILE NOT FOUND(`LOAD X`), SYNTAX ERROR, VOLUME MISMATCH(`CATALOG,V99`), RANGE ERROR, WRITE PROTECTED(쓰기 금지 디스크 이미지), NO BUFFERS AVAILABLE, NOT DIRECT COMMAND(프롬프트에서 `READ`). 준비가 필요한 것: DISK FULL, I/O ERROR, LANGUAGE NOT AVAILABLE, END OF DATA, PROGRAM TOO LARGE.
- 이 디스크의 DOS는 22/21줄에서 쪽을 넘기고 표준 24/23줄이 아닙니다(`DOS_PATCHES.md`). 다른 DOS는 고치기 전에 같은 명령어 확인이 필요합니다.
- K-BASIC 애드온은 자기 메시지가 따로 있으므로 이 훅을 알아야 하는지 그 세션과 정해야 합니다.


## 5. 한글 파일 이름

**짧은 답: 한글만으로 된 이름은 지금은 안 되지만, 작은 DOS 패치 하나(약 20~30바이트, 5.2절)로 됩니다.** DOS는 첫 글자가 영어 글자가 아닌 이름을 거부합니다. 지금은 이름이 영어 글자로 시작해야 합니다(`A한`은 됨). 패치를 하면 `한글` 같은 온전한 한글 이름이 됩니다. 한계는 5.5절: 이름 하나에 7~9음절 정도, 한글 앞뒤에 Ctrl-K ... Ctrl-A를 쳐야 함, 5.4절의 쉼표 문제.

### 5.1 DOS가 파일 이름을 읽는 방법

DOS는 친 이름을 30바이트 영역(빈칸 `$A0`으로 채움)에 복사합니다. 반복문은 `$A043-$A061`입니다.

1. `$A043`: 이름의 첫 글자를 읽습니다(`JSR $A1A4`, 빈칸은 건너뜀). 이름이 비었으면 끝.
2. `$A048`: `ASL A; BCC $A050; BMI $A050; JMP $A000`. **첫 글자는 `$C0-$FF`**, 즉 최상위 비트가 켜진 글자여야 합니다. 그 밖의 것(숫자, 구두점, Ctrl-K `$8B` 같은 제어 코드)은 `$A000`으로 가서 `?SYNTAX ERROR`가 납니다. 이름은 글자로 시작해야 한다는 DOS의 규칙입니다.
3. `$A054-$A061`: **나머지 글자는 아무 검사 없이 복사됩니다.** 쉼표나 줄 끝까지입니다. 30바이트가 넘으면 문법 오류입니다(`$A078`, `$A092`).

드라이버가 입력 줄에 넣는 것: Ctrl-K(`$8B`), 자모 키(최상위 비트가 켜짐, 영어 대문자와 같음), Ctrl-A(`$81`). 쌍자음 키는 `- = * < > ; +`이고 쉼표는 없으므로 한글 구간이 이름을 일찍 끝내지 않습니다. 걸림돌은 첫 글자 검사뿐입니다. 이름은 카탈로그에 그대로 저장됩니다.

`CATALOG`는 `$AE18`에서 이름 30바이트를 하나씩 `JSR $FDED`(출력 연결)로 보냅니다. 거르는 곳이 없으므로 Ctrl-K, 자모, Ctrl-A가 드라이버에 닿아 한글로 보입니다. `CATALOG`는 바꿀 필요가 없습니다.

### 5.2 하려면 무엇이 드는가

**영어 글자로 시작하는 이름: 지금 됨, 변경 없음.** 사용자가 첫 글자를 영어 모드로 치고 한글로 바꿉니다: `SAVE A`, Ctrl-K, 한글 키, Ctrl-A. 설명서에 한 단락 쓰면 됩니다.

**한글로 시작하는 이름.** `$A04D`의 `JMP $A000`을 카드 안 루틴으로 가는 `JMP`로 바꿉니다. `ASL A` 뒤에 Ctrl-K는 `$16`입니다. 루틴은 `CMP #$16`, 같으면 `$A050`으로 `BEQ`, 아니면 `JMP $A000`.

| 항목 | 바이트 (추정) |
|---|---|
| 카드 안 루틴 | 8~12 |
| 연결부 (`CATINIT`과 같은 종류) | 7~15 (같은 입구를 쓰면 메시지와 나눠 쓸 수 있음) |
| 재구성 입구 | 몇 바이트 |
| **합계** | **약 20~30** |

작업: 시험 포함 반나절(고치기 전에 DOS 원래 바이트를 확인하고, 재구성 입구에서 패치를 다시 만들어야 함). 첫 글자 검사를 없애는 대안은 카드 공간이 안 들지만 숫자나 구두점으로 시작하는 이름도 받아들이고, 이름 첫머리를 잘못 쳐도 저장됩니다. 권하지 않습니다.

### 5.3 MAME 시험

`disk\K-HANGEUL.DSK`의 복사본으로 DOS를 부팅(보통 16KB 카드)하고, 자판으로 Ctrl-K와 Ctrl-A를 넣어 명령을 쳤습니다. 화면은 하이레스 화면에서, 디스크는 `acx`로 읽었습니다.

| 시험 | 결과 |
|---|---|
| `SAVE A` Ctrl-K `GKS` Ctrl-A (이름 `A한`) | 저장됨. 카탈로그 항목은 `A`, `$8B`, `GKS` |
| 같은 방식으로 `B각`, `R한`, `C한` | 저장됨 |
| `SAVE` Ctrl-K `SKR` Ctrl-A (한글로 시작) | `?SYNTAX ERROR`, 저장 안 됨 |
| `NEW` 뒤 `LOAD A한` | 프로그램이 돌아옴(프로그램 끝 `$0440` → `$0940`) |
| `DELETE A한` | 카탈로그에서 사라짐 |
| `CATALOG` | `A 002 A한`, `B 002 B각` 줄이 나오고 한글이 제대로 그려짐 |
| `RUN R한` (프로그램 `10 POKE 785,77`) | 실행됨: `PEEK(785)`가 0에서 77로 |
| `BSAVE B,A768,L4`, `RENAME B,C한`, `BRUN C한` (`$0310`에 1을 더하는 기계어) | `$0300`에 불러와 실행됨: `$0310`이 0에서 1로 |
| `BSAVE B한,A768,L4` (한글 이름 뒤에 쉼표) | **`?SYNTAX ERROR`**, 5.4절 참고 |
| Ctrl-A를 빼고 이름을 침 | 저장되고 읽히지만 **드라이버가 한글 모드에 머묾**: 다음에 치는 줄이 한글로 나와 `?SYNTAX ERROR`. Ctrl-A를 누르면 풀림 |

확인하지 못한 것: 한글 첫 이름을 쓰는 `LOCK` / `UNLOCK`과 `RENAME`(같은 쉼표 문제로 시험 줄이 깨짐), 텍스트 파일 명령(`OPEN`, `READ`, `WRITE`)과 `BLOAD`, Ctrl-A 없이 저장된 이름이 `CATALOG`에서 어떻게 보이는지(드라이버가 한글 구간을 다음 칸까지 열어 둘 수 있음), Saturn 카드와 IIe 이후 기종.

### 5.4 쉼표 문제

드라이버의 줄 편집기는 닫는 Ctrl-A(`$81`)를 **바로** 줄에 쓰지 않습니다. 다음 **글자**가 오거나 Return을 칠 때 씁니다(`driver.s`의 `CLOSERUN`, `L_E70C`). 쉼표, 빈칸, 숫자는 그것을 일으키지 않습니다. 그래서 `BSAVE B` Ctrl-K `GKS` Ctrl-A `,A768,L4`는 줄에 `B`, `$8B`, `GKS`, `,`, `$81`, `A768,L4`로 들어갑니다. DOS는 쉼표에서 이름을 끝내고 옵션 칸 머리에서 남은 `$81`을 만나 문법 오류를 냅니다. 한글 이름 뒤에 뭐가 더 오는 명령은 모두 같습니다.

지금 피하는 방법: 한글 이름을 줄의 **맨 끝**에 두거나, 영어 이름으로 저장하고 `RENAME 옛이름,새이름`(한글 새 이름이 끝)으로 바꿉니다. 위 `BRUN` 시험이 그렇게 했습니다.

제대로 고치려면 줄 편집기를 조금 고쳐 쉼표(그리고 아마 빈칸)에서도 닫는 Ctrl-A를 쓰게 합니다. 드라이버를 고치는 일이고 아직 건드리지 않았습니다. 한글 명령 별명(6절)도 같은 문제를 겪습니다: `목록,D2`는 `$8B`, 자모, `,`, `$81`, `D2`로 들어오므로 별명 루틴이 이를 감당해야 합니다.

### 5.5 한계와 위험

- **길이.** 한 음절이 키 코드 2~4개입니다(`한` = `GKS` 3바이트, 겹받침은 4). Ctrl-K와 Ctrl-A가 2개 더 듭니다. 30바이트 한도에서 이름 하나는 **7~9음절** 정도이고, 영어가 섞이면 더 적습니다.
- **다른 컴퓨터와 도구.** 디스크에는 표준 한글 부호가 아니라 자판 코드가 들어 있습니다. 일반 Apple II의 `CATALOG`는 제어 코드와 글자를 찍고 `acx`에서는 `A<Ctrl-K>GKS`로 보입니다. 파일은 여전히 되지만 이 드라이버 밖에서 이름은 잡음처럼 보입니다. 남에게 주는 디스크는 영어 이름을 쓰세요.
- **Ctrl-A가 필요합니다**(5.3절 표).
- **일치는 바이트 단위.** 드라이버의 조합 규칙이 음절마다 한 순서만 주므로 같은 낱말은 늘 일치할 것으로 보지만, 다른 순서로 쳐 본 시험은 하지 않았습니다.
- **프로그램 안.** `PRINT CHR$(4);"LOAD A..."`에서는 한글 코드를 문자열에 직접 넣어야 합니다(`CHR$(11)` 등). 프로그램 작성자의 몫입니다.
- **정렬.** DOS는 카탈로그를 정렬하지 않으므로 문제 없습니다.


## 6. 한글 명령 이름

`CATALOG` 대신 `목록`, `SAVE 이름` 대신 `저장 이름`.

28개 명령을 한 줄씩 적고 한글 제안을 붙였습니다. "별명?"은 제 권고입니다. **예** = 프롬프트에서 자주 쳐서 별명을 둘 만함, **선택** = 주로 프로그램 안에서 쓰고 나중에 하나 더해도 싸다(하나에 6~12바이트), **아니오** = 영어로 둠. 이름은 검토용 초안입니다. 마지막 칸은 K-BASIC 세션의 답을 적을 자리입니다(표 아래 설명 참고).

**K-BASIC 답(물어서 그쪽 소스를 읽은 결과):** K-BASIC은 DOS 명령에 한글 이름을 주지 않습니다. 모두 영어로 둡니다(그쪽 문서에 "한글 DOS 명령: 안 함"이라고 있음). 겹치는 것은 애플소프트 낱말뿐입니다. **`실행` = RUN, `읽기` = READ**는 이미 K-BASIC 낱말입니다. K-BASIC은 애플소프트가 낱말을 토큰으로 바꾸기 전에 친 줄을 고쳐 쓰므로(드라이버의 줄 입력에서 부르는 `KB_IN` 훅), K-BASIC을 올렸으면 `실행 이름`이 DOS나 애플소프트가 보기 전에 `RUN 이름`이 됩니다(DOS와 함께는 시험하지 않았습니다). 큰따옴표 안의 글은 그대로 두므로 `PRINT CHR$(4);"..."`는 건드리지 않습니다. `PR#`, `IN#`은 K-BASIC이 건드리지 않는 애플소프트 낱말입니다. 그러므로 표의 이 두 단어는 정확히 `실행`, `읽기`로 두어야 합니다.


**K-BASIC 낱말과 겹침 검사:** 제안한 한글 이름을 K-BASIC의 `keywords.tsv`(98줄)와 맞춰 봤고, K-BASIC 세션이 자기 소스(`kbasic.s`)로 다시 확인해 주었습니다.

- **K-BASIC의 비교 방식:** 낱말 전체가 아니라, 줄을 한 키씩 훑으며 한글 덩어리 안의 모든 위치에서 표를 맞춰 봅니다(낱말 경계 검사 없음). 표 순서대로 처음 맞는 것을 쓰고 가장 긴 것을 먼저 쓰지는 않습니다. 따라서 이름 안에 K-BASIC 낱말이 들어 있으면 일부만 바뀝니다(큰따옴표, REM, DATA 안은 그대로).
- **첫 초안에서 겹쳐 바꾼 것(3개):** INIT `초기화`(CLEAR) → `포맷`, DELETE `삭제`(DEL)는 빼고 `지우기`만, POSITION `위치`(POS) → `자리`.
- **K-BASIC 세션이 찾은 것(4개):** 낱말이 이름 안에 들어 있는 경우였습니다. `이어실행`→`이어RUN`, `일괄실행`→`일괄RUN`, `이진실행`→`이진RUN`(모두 `실행`=RUN 포함), `이진읽기`→`이진READ`(`읽기`=READ 포함). 그래서 CHAIN `연결`, EXEC `일괄`, BRUN `이진가동`, BLOAD `이진불러오기`로 바꿨습니다. 이 네 이름은 K-BASIC 목록과 맞춰 봤지만 K-BASIC 세션이 다시 시험해 준 것은 아닙니다.
- **남은 겹침:** `실행`(RUN)과 `읽기`(READ)뿐이며 같은 명령이라 문제 없습니다. `저장`은 K-BASIC의 `테이프저장`(STORE)과 다릅니다(앞부분이 아님).
- **안전장치:** 드라이버가 줄의 첫 낱말을 먼저 영어 명령으로 바꾸면 K-BASIC의 훑기는 그 낱말을 보지 못합니다. 별명을 드라이버에 두는 결정과 맞습니다. `감시`와 `감시끝`처럼 한 이름이 다른 이름의 앞부분이면 긴 쪽을 먼저 맞춰야 합니다.

### 6.1 메시지보다 어려운 이유

- **해석기는 글자를 비교합니다.** DOS는 `$A884`의 표에서 단어를 찾습니다. 한글 모드에서 친 한글 단어는 `$8B`, 자모 키, `$81`로 들어오므로 표와 맞지 않습니다(`?SYNTAX ERROR`). 또 명령 단어 앞에서 한글 모드를 켜고(Ctrl-K ... Ctrl-A) 파일 이름 앞에서 꺼야 하며, 누르는 키 수는 영어 단어와 비슷합니다.
- **방법: DOS가 줄을 보기 전에 별명을 바꿔 줌.** 줄 입력이 끝나면(Return) 드라이버가 첫 단어를 보고, 한글 별명과 같으면 줄 버퍼에서 영어 명령으로 바꿉니다. DOS와 Applesoft는 그대로입니다. 별명 10~14개 표(하나에 6~12바이트)와 비교 루틴이 필요합니다. (DOS 해석기 안에 두 번째 이름표를 넣는 방법은 더 크고 위험합니다. 권하지 않습니다.)
- **아직 확인하지 않은 것(MAME에서 봐야 함):** 직접 모드에서 DOS가 친 명령을 정확히 어디서 읽는지, 그리고 드라이버의 줄 입력이 바꿔치기에 맞는 자리인지. 별명 방법이 간단한지는 이것으로 정해지므로 먼저 확인해야 합니다(약 반나절).
- **쉼표 문제(5.4절)**가 적용됩니다. 별명 루틴이 쉼표나 빈칸 뒤에 `$81`이 오는 것을 감당하거나, 줄 편집기를 고쳐야 합니다.
- **프로그램 안**(`PRINT CHR$(4);"CATALOG"`)의 글은 프로그램 작성자가 쓰는 영어입니다. 출력 쪽에서 바꾸면 거기도 적용되지만 그것은 따로 정할 더 큰 문제입니다.

| 재구성 입구 수정 | 몇 바이트 |
| **합계** | **약 160~240** |

별명을 나중에 하나 더하면 약 6~12바이트입니다. 작업량: 1~2일. 미확인 사항과 시험할 경우(줄 맨 앞에서만, `목록,D2`, 대소문자, 영어와 한글 섞기, 드라이버가 꺼진 경우)가 많기 때문입니다.

### 6.3 별명은 누가 하나: 카드인가, K-BASIC인가?

K-BASIC이 이미 DOS가 보기 전에 친 줄을 고쳐 쓰므로, 같은 장치에 한글 DOS 낱말을 실어 카드 대신 할 수 있습니다. K-BASIC 세션도 가능하다고 보지만, 별도의 표(애플소프트 낱말용인 `keywords.tsv`가 아닌)와 별도의 코드가 필요하고, 그쪽 모듈은 `$9400` 아래 여유가 약 1바이트뿐이라고 합니다.

| | 드라이버 카드 (6.2) | K-BASIC |
|---|---|---|
| 쓰는 메모리 | 카드 160~240바이트, 여유는 669바이트뿐 | BASIC 메모리(`HIMEM`이 비슷한 양만큼 내려감, 여유 21,501바이트 중) |
| K-BASIC 없이 되나 | 예 | 아니오 (K-BASIC 쓰는 사람만) |
| 따옴표, 주석 | 새로 써야 함 | 이미 처리됨 (따옴표 안은 그대로 둠) |
| 쉼표 문제(5.4절) | 처리해야 함 | 그쪽 줄 고쳐쓰기에서 확인해야 함 |
| 프로젝트 | 하나 | DOS 낱말 목록이 K-BASIC에 들어감. 이 보고서는 낱말만 제안 |

**결정(2026-11-02, 사용자): 한글 명령과 메시지를 모두 드라이버가 합니다. K-BASIC은 하지 않습니다.** K-BASIC 세션에는 분석을 멈추라고 했습니다. 이유: K-BASIC 없이도 되고, DOS에 관한 것이 한 프로젝트에 모입니다. 대가는 카드의 빈 자리입니다(8절의 크기 표). 위 비교표의 K-BASIC 열은 참고용으로 남겨 둡니다.

## 7. 하지 말아야 할 것

- DOS 해석기 안에 두 번째 명령 이름표를 넣는 것(6.1절).
- `MON` / `NOMON`, `FP`, `INIT` 같은 말없는 명령: 옮길 것이 없습니다.
- `CATALOG`의 종류 글자(`T I A B S R`)를 한글로 바꾸기: 같은 반복 고침으로 가능하지만 사람들이 아는 한 글자 표시라서 얻는 것이 작습니다.


## 8. 결정된 것과 정해 주실 것

### 8.1 지금까지 정해진 것

| # | 결정 | 이유 |
|---|---|---|
| 1 | 오류 메시지와 `CATALOG` 머리글은 **드라이버**가 한글로 한다 | 메시지는 DOS의 `$A702`가 일반 출력(COUT)으로 찍는다. K-BASIC의 출력 훅은 LIST 전용이고, 한글 글자를 그리는 출력 훅과 "출력이 바뀌면 영어로" 대체 동작은 드라이버에 있다. |
| 2 | 한글 명령 이름(별명)도 **드라이버**가 한다. K-BASIC은 하지 않는다 (사용자 결정, 2026-11-02) | K-BASIC 없이도 되고, DOS에 관한 것이 한 곳에 모인다. K-BASIC 세션에는 분석 중단을 알렸다. |
| 3 | 한글 이름이 K-BASIC 낱말과 겹치지 않게 7개를 바꿨다 | `초기화`→`포맷`, `삭제` 뺌, `위치`→`자리`, `이어실행`→`연결`, `일괄실행`→`일괄`, `이진실행`→`이진가동`, `이진읽기`→`이진불러오기` (6.의 검사 참고). 예외는 같은 명령인 `실행`(RUN)과 `읽기`(READ). |
| 4 | 별명은 줄의 첫 낱말만 보고, 드라이버가 K-BASIC보다 먼저 영어 명령으로 바꾼다 | 그러면 K-BASIC의 훑기는 그 낱말을 보지 못한다. 한 이름이 다른 이름의 앞부분이면(`감시`/`감시끝`) 긴 쪽을 먼저 맞춘다. |
| 5 | 영어 글자로 시작하는 한글 파일 이름은 지금도 되므로 설명서에 쓴다 | 5절의 MAME 시험. |

### 8.2 크기: 다 들어가는가?

| 항목 | 바이트 | 빈 자리 669 중 |
|---|---|---|
| 메시지 + 머리글 | 380~410 | |
| 한글 명령 별명 (전부) | 160~240 | |
| **둘 합계** | **540~650** | 남는 것 19~129 |
| 한글로 시작하는 이름 | 20~30 | 합계에 더하면 거의 가득 |
| `./이름` 실행 명령 | 110~180 | 들어가지 않음 |

별명 크기 160~240은 추정이고 Saturn 뱅크의 빈 자리는 다시 재지 않았습니다. 줄이는 방법: 별명을 "예"인 9개(INIT, LOAD, SAVE, RUN, DELETE, LOCK, UNLOCK, RENAME, CATALOG)만 두면 60~90바이트로 줄 것으로 보입니다. 이것은 추정입니다. 그 밖에 메시지 문구를 더 줄이거나 플레인 카드의 `$0800-$1FFF` 빈 자리(93바이트)와 Saturn `$9400` 조각을 쓰는 방법이 있습니다. 새 DOS 훅마다 재구성 입구(`SATREINIT=$D3FA`)에 몇 바이트가 더 듭니다.

### 8.3 권고와 정해 주실 것

1. **메시지와 `CATALOG` 머리글을 하세요**(4절). 두 카드에 함께 하고 재구성 진입점에 훅을 추가합니다.
2. **영어 글자로 시작하는 이름의 한글**(지금도 됨)을 설명서에 쓰고 Ctrl-A 규칙과 쉼표 피하는 방법도 적습니다.
3. **한글로 시작하는 이름**(5.2절)을 메시지와 함께 허용합니다. 20~30바이트뿐입니다.
4. **별명**: 8.2의 크기 때문에 처음에는 "예"인 9개로 시작하고 나머지는 자리가 남을 때 더하는 것을 권합니다. 먼저 MAME에서 미확인 사항(6.1절, 반나절)을 확인합니다. 결정해 주실 것: 9개로 시작할지 28개 전부를 목표로 할지.
5. **`./이름`**은 크기 때문에 지금은 맞지 않습니다. 보류하거나 다른 것을 줄여야 합니다. 정해 주세요.
6. 파일 이름이나 별명 뒤에 옵션이 오는 경우까지 되게 하려면 **줄 편집기의 쉼표 문제를 고치세요**. 원하시면 말씀해 주세요. 드라이버를 고치는 일입니다.
7. 만들기 전에: 한글 문구를 검토하고, Saturn 뱅크의 빈 자리를 다시 재고, 새로 바꾼 이름 4개를 K-BASIC 세션에 시험해 달라고 합니다.
8. 버전 규칙에 따라 이것은 변경 사항입니다. VERSION은 말씀하실 때만 올립니다.
