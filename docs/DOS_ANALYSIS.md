# DOS 3.3 명령어 한글화: 비용과 가능성

> English version: [DOS_ANALYSIS_en.md](DOS_ANALYSIS_en.md)


이 문서는 DOS 3.3의 어느 부분을 한글로 보여 줄 만한지, 메모리와 작업이 얼마나 드는지, 무엇은 할 수 없는지를 따져 봅니다. 분석만 한 것이고, 여기 적힌 것은 아직 하나도 만들지 않았습니다.

아래 사실을 알아낸 방법: `disk\K-HANGEUL.DSK`의 DOS를 MAME에서 켜고 메모리(`$9600-$BFFF`)를 떠서 읽었습니다. 주소는 그 DOS(이 프로젝트가 `DOS_PATCHES.md`대로 고친 것)의 주소입니다. MAME에서 실제로 해 본 것은 그렇다고 적었고, 나머지는 메모리에서 읽었거나 "추정"이라고 적었습니다.


## 1. DOS 명령어 전체

DOS 3.3의 명령어는 28개입니다. 이름은 `$A884`의 표에 있습니다. 이 디스크에서는 `INT`가 `HAN`으로 바뀌어 있습니다(`DOS_PATCHES.md` 참고).

| 명령 | 하는 일 | 화면에 뭘 찍나 | 한글화할 만한가 |
|---|---|---|---|
| `INIT` | 디스크를 포맷하고 DOS를 씁니다 | 없음 (오류만) | 아니오 |
| `LOAD` | BASIC 프로그램을 불러옵니다 | 없음 (오류만) | 아니오 |
| `SAVE` | BASIC 프로그램을 저장합니다 | 없음 (오류만) | 아니오 |
| `RUN` | 불러와서 실행합니다 | 없음 (오류만) | 아니오 |
| `CHAIN` | 변수를 지키면서 다른 프로그램을 실행합니다 | 없음 (오류만) | 아니오 |
| `DELETE` | 파일을 지웁니다 | 없음 (오류만) | 아니오 |
| `LOCK` / `UNLOCK` | 파일을 보호하거나 풉니다 | 없음 (오류만) | 아니오 |
| `RENAME` | 파일 이름을 바꿉니다 | 없음 (오류만) | 아니오 |
| `OPEN` / `CLOSE` | 텍스트 파일을 열고 닫습니다 | 없음 (오류만) | 아니오 |
| `READ` / `WRITE` / `APPEND` / `POSITION` | 텍스트 파일 읽기/쓰기 | 없음 (오류만) | 아니오 |
| `EXEC` | 텍스트 파일을 명령처럼 실행합니다 | 없음 (오류만) | 아니오 |
| `CATALOG` | 디스크의 파일 목록을 보여 줍니다 | **목록** (머리글, 볼륨 번호, 종류, 크기, 이름) | **예** |
| `MON` / `NOMON` | 디스크 입출력 기록을 화면에 보이거나 숨깁니다 | `MON`일 때만 기록 줄 | 아니오 (거의 안 씀) |
| `PR#` / `IN#` | 출력/입력 슬롯을 고릅니다 | 없음 | 아니오 |
| `MAXFILES` | 파일 버퍼 수를 정합니다 | 없음 | 아니오 (`HIMEM`도 깨뜨립니다. `DOS_PATCHES.md` 참고) |
| `FP` / `HAN` | 애플소프트로 바꿉니다 / 한글 드라이버를 다시 켭니다 | `HAN`의 시작 화면 (이미 한글) | 이미 됨 |
| `BSAVE` / `BLOAD` / `BRUN` | 바이너리 파일 저장/불러오기/실행 | 없음 (오류만) | 아니오 |
| `VERIFY` | 파일을 읽을 수 있는지 확인합니다 | 없음 (오류만) | 아니오 |

결과: 대부분의 명령은 잘 되면 아무것도 찍지 않습니다. 사용자가 보는 것은 두 가지입니다. 모든 명령이 같이 쓰는 **오류 메시지**(14개)와 **`CATALOG` 목록**입니다. 한글화할 만한 것은 이 둘뿐입니다.


## 2. DOS가 무엇을 어디서 찍나

### 2.1 오류 메시지 (14개)

- 글자는 `$A971-$AA3E`(202글자)에 있고, 시작 위치 표가 `$AA3F`에 있습니다. 각 메시지의 마지막 글자만 최고 비트가 켜져 있습니다.
- 메시지 하나를 찍는 루틴이 `$A702`에 있습니다. `X`가 메시지 번호이고, 시작 위치를 읽은 뒤 글자마다 `JSR $9FC5`(DOS의 출력 루틴. 끝에서 드라이버의 출력 훅으로 들어갑니다)로 보내다가, 최고 비트가 켜진 글자에서 멈춥니다. 14개 오류 메시지와, 오류마다 먼저 나오는 줄바꿈/종소리가 모두 이 루틴을 지납니다.
- 메시지: LANGUAGE NOT AVAILABLE, RANGE ERROR, WRITE PROTECTED, END OF DATA, FILE NOT FOUND, VOLUME MISMATCH, I/O ERROR, DISK FULL, FILE LOCKED, SYNTAX ERROR, NO BUFFERS AVAILABLE, FILE TYPE MISMATCH, PROGRAM TOO LARGE, NOT DIRECT COMMAND.

### 2.2 `CATALOG` 목록

- 머리글 "DISK VOLUME "은 `$B3A7`에 거꾸로 저장되어 있습니다(같은 표 앞쪽에 파일 종류 글자 8개 `T I A B S R A B`가 있습니다). `$ADB0`의 루틴이 11바이트짜리 반복으로 찍습니다: `LDX #$0B / LDA $B3AF,X / JSR $FDED / DEX / BPL`.
- 그다음: 볼륨 번호(3자리), 그리고 파일마다 잠금 표시 `*`, 종류 글자, 섹터 수(3자리), 30글자 이름.
- 화면을 넘길 때 멈추는 부분(`DOS_PATCHES.md`의 `CATINIT`, `CATWAIT` 고침)은 이미 되어 있습니다.

### 2.3 DOS가 아닌 것

애플소프트 메시지(`?SYNTAX ERROR`, `?OUT OF MEMORY` 등)는 애플 II 롬에 있고 K-BASIC 프로젝트의 몫입니다. 이 분석에 들어 있지 않습니다.


## 3. 한글 메시지를 어떻게 찍나

드라이버는 사용자가 치는 것과 같은 키 입력 글(`$8B`(Ctrl-K)로 한글 구간 시작, 자모 키들, `$81`(Ctrl-A)로 끝)을 받으면 이미 한글을 보여 줍니다. 그래서 한글 메시지는 같은 출력 훅으로 다른 글자열을 보내기만 하면 됩니다. 드라이버의 그리기를 고칠 필요는 없습니다.

영어 글을 그 자리에서 덮어쓸 수는 없습니다. 한글 쪽이 더 길기 때문입니다(4.1 참고).

**계획:** 메시지 루틴을 우리 루틴으로 바꿉니다.

1. DOS는 `$A702`를 불러 메시지 `X`를 찍습니다. 그 루틴의 첫 3바이트를 랭귀지 카드 안의 루틴으로 가는 `JMP`로 고칩니다.
2. 새 루틴이 같은 `JSR $9FC5` 반복으로 한글 메시지를 찍습니다.
3. 한글 드라이버가 출력을 맡고 있지 않으면(`PR#0` 뒤나 Ctrl-Reset 뒤) 새 루틴은 원래 영어 루틴으로 넘깁니다. 그래서 한글 글자열이 일반 글자 화면으로 가는 일은 없습니다.

`CATALOG` 머리글도 같은 방법입니다. `$ADB0`의 11바이트 반복을 `디스크 볼륨 `을 찍는 호출로 바꿉니다(같은 대체 동작 포함).

프로그램이 `$9400-$95FF`를 덮어써도(kScheme이 그렇게 합니다) 이 훅이 사라지면 안 됩니다. 이미 쓰는 DOS 고침(`CATINIT`, `CATWAIT`)이 그 블록을 가리키고 그것을 `$D3FA`의 재구성 진입점이 다시 만들어 줍니다. 새 훅도 재구성 진입점이 다시 만드는 것에 들어가야 합니다.


## 4. 비용

### 4.1 크기

한글 문구는 초안입니다. 크기는 메시지마다 `src\tools\nbyte.py`로 인코딩해서 계산했습니다.

| 항목 | 지금(영어) | 한글(키 입력 글) |
|---|---|---|
| 오류 메시지 14개 | 202바이트 | 312바이트 |
| `CATALOG` 머리글 | 12바이트 | 18바이트 |
| 시작 위치 표 | 15바이트 | 14바이트 |
| 새 루틴 (메시지 찍기, 머리글 찍기, 대체 동작 검사) | – | 약 60-80바이트 (추정) |
| DOS에서 카드로 들어가는 짧은 중계 코드 (메인 램 또는 트램펄린 블록) | – | 7-15바이트 (추정) |

- 카드 안 합계: 약 **410-430바이트**. 일반 16KB 카드는 `$D133-$D3FF`에 717바이트가 비어 있습니다. 이 빌드에서는 `$D3D0-$D3FF`를 시프트 마스크와 재구성 진입점이 쓰므로 실제로 비어 있는 것은 약 669바이트(`$D133-$D3CF`)입니다. 약 240바이트 여유를 두고 들어갑니다. Saturn 뱅크도 같은 주소에 같은 만큼의 자리가 있습니다. (뱅크 안의 빈 자리는 다시 재지 않았습니다. 만들기 전에 재야 합니다.)
- 중계 코드: 일반 카드에서는 메인 램 `$0800-$1FFF`에 93바이트만 비어 있어서 하나는 들어갑니다. Saturn 카드에서는 `$9400-$95FF` 블록에 조각조각 약 49바이트가 비어 있어서 7-15바이트짜리 하나가 들어갑니다.
- BASIC 메모리: **그대로** (`HIMEM`은 `$9400`, 21,501바이트 여유).
- 영어 원문은 DOS에 그대로 남으므로 대체 동작을 위한 복사본이 따로 필요 없습니다.

### 4.2 작업량 (추정)

| 단계 | 작업량 |
|---|---|
| 한글 메시지 14개와 머리글을 쓰고 확인 (문구는 검토해 주셔야 합니다) | 작음 |
| 메시지 루틴, 머리글 루틴, DOS 고침 둘, 중계 코드 | 약 반나절 |
| 안전하게 만들기: 고치기 전에 DOS 바이트를 확인(`CATINIT`처럼), 영어 경로 유지, 재구성 진입점에 훅 추가 | 약 반나절 |
| 메시지마다 MAME 시험 (아래 참고), 일반 카드와 Saturn 카드 모두 | 약 반나절 |

### 4.3 위험

- 드라이버가 꺼져 있는데 한글을 보내면 깨진 글자가 나옵니다. "출력 훅이 드라이버 것인가" 검사로 막는데, `PR#0`과 Ctrl-Reset 상태에서 시험해야 합니다.
- 한글은 영어보다 화면에서 넓습니다. 오류 줄은 짧아서 줄이 넘칠 일은 없어 보이지만 46열 화면에서 하나씩 봐야 합니다.
- 메시지마다 시험할 방법이 있어야 합니다. FILE NOT FOUND(`LOAD X`), SYNTAX ERROR, VOLUME MISMATCH(`CATALOG,V99`), RANGE ERROR, WRITE PROTECTED(쓰기 금지 디스크 이미지), NO BUFFERS AVAILABLE, NOT DIRECT COMMAND(프롬프트에서 `READ`)는 쉽습니다. DISK FULL, I/O ERROR, LANGUAGE NOT AVAILABLE, END OF DATA, PROGRAM TOO LARGE는 준비가 필요합니다.
- 이 디스크의 DOS는 22/21줄에서 쪽을 넘기고 표준 DOS의 24/23줄이 아닙니다(`DOS_PATCHES.md`). 다른 DOS는 고치기 전에 같은 명령어 확인이 필요합니다.


## 5. 하지 말아야 할 것

- **한글 명령 이름** (`CATALOG` 대신 `목록`): 명령 해석기는 `$A884` 표의 글자와 맞춰 보는데, 한글 단어는 명령마다 먼저 한글 모드를 켜야 합니다. 새 해석 경로와 두 번째 이름 표(100바이트 넘게)가 필요한데 얻는 것이 작습니다. 권하지 않습니다.
- **한글 파일 이름**: MAME에서 한 번 해 봤습니다. `SAVE` 뒤에 Ctrl-K와 한글 키를 치니 `?SYNTAX ERROR`가 나왔습니다(제어 코드 `$8B`를 이름에 받아 주지 않습니다). 되게 하려면 DOS의 이름 해석기와 카탈로그의 30바이트 이름 형식을 고쳐야 합니다. 권하지 않습니다.
- **`MON` / `NOMON`**, `FP`, `INIT` 같은 말없는 명령: 옮길 것이 없습니다.
- `CATALOG`의 종류 글자(`T I A B S R`)를 한글로 바꾸기: 같은 반복 고침으로 가능하지만 한 글자씩 세로로 늘어선 낯익은 표시라서 얻는 것이 작습니다.


## 6. 권하는 것

1. **오류 메시지 14개**와 **`CATALOG` 머리글**: 하세요. DOS가 사용자에게 읽히게 보여 주는 것은 이것뿐이고, 비용은 지금 비어 있는 카드 약 420바이트이며 BASIC 메모리는 쓰지 않습니다.
2. 두 카드에 함께 하고, 영어 대체 동작을 넣고, 재구성 진입점에 훅을 추가합니다.
3. 5번 항목은 건너뜁니다.

만들기 전에: 한글 문구를 검토하고, Saturn 뱅크의 빈 자리를 다시 재고, (자기 메시지가 따로 있는) K-BASIC 애드온이 이 훅을 알아야 하는지 K-BASIC 세션과 정합니다.
