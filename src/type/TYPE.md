# TYPE: `&TYPE` 명령

`TYPE`은 애플소프트 BASIC에 명령 하나를 더합니다. N바이트(자판 입력) 방식의 한글 글을 찍습니다. DOS 텍스트 파일에서 읽거나 메모리에서 찍습니다. 선택 사항이라 필요 없는 프로그램은 올리지 않아도 됩니다. 명령은 `& TYPE,...` 또는 `&TYPE,...`처럼 쓰거나, `& "TYPE",...`처럼 따옴표로 묶어 쓸 수 있습니다. 공백은 상관없습니다.

> English version: [TYPE_en.md](TYPE_en.md)



N바이트 글은 자판으로 한글을 칠 때 나오는 바이트입니다. Ctrl-K(`$0B`), 대문자 2벌식 자모, Ctrl-A(`$01`) 순서입니다. 영문, 숫자, 문장부호는 그 바깥에 있습니다. 모든 바이트는 화면 출력 루틴을 거치므로 K-HANGEUL 드라이버가 한글을 조합합니다. 드라이버가 없으면 바이트는 영문자로 찍힙니다.


## 사용법

```basic
10 PRINT CHR$(4);"BRUN TYPE"          : REM 처음에 한 번 올린다
20 & TYPE,"NALGAE1"                  : REM DOS 텍스트 파일
30 & TYPE,"NALGAE" + STR$(N)         : REM 어떤 문자열 식이든 된다
40 PRINT CHR$(4);"BLOAD MYTEXT,A$8000"
50 & TYPE,"$8000"                    : REM 메모리의 글, 16진수 주소
60 & TYPE,"A$8000"                   : REM 같은 것, DOS 식
70 & TYPE,32768                      : REM 같은 것, 10진수
```

| 두 번째 인자 | 뜻 |
|---|---|
| `$` 또는 `A$`로 시작하고 16진수 1~4자리가 붙은 문자열 | 16진수 주소 |
| 그 밖의 문자열 | DOS 파일 이름(최대 30자) |
| 숫자 | 10진수 주소 |

디스크에는 예제가 두 개 있습니다. `RUN TYPEDEMO`는 예제 글을 세 가지 방법으로 찍고, `RUN STORYT`는 `&TYPE` 한 줄을 반복문에서 써서 「날개」 전체를 찍습니다.


### 파일에서 찍기

`& TYPE,"이름"`은 파일을 직접 읽습니다. 디스크 목록(카탈로그)에서 이름을 찾고, DOS의 RWTS 루틴으로 데이터 섹터를 읽습니다. 그래서 `OPEN`이나 `READ`를 쓰지 않습니다. 이것은 다음 세 가지 뜻입니다.

- `]` 프롬프트에서 쳐도 됩니다. 예: `& TYPE,"SAMPLE1"`.
- 파일을 열어 둘 수 없으므로 `CLOSE`, `ONERR`, 버퍼가 필요 없습니다.
- DOS처럼 마지막에 쓴 디스크 동작의 슬롯과 드라이브를 씁니다.

이름은 대문자로 바꿔 찾으므로 `"nalgae1"`도 됩니다. 파일은 DOS 텍스트 파일(종류 T)이어야 합니다. 다른 종류는 `FILE TYPE MISMATCH`가 나옵니다. 디스크에 없는 이름은 DOS 오류 `FILE NOT FOUND`(오류 6)가 나옵니다. 프로그램 안에서는 `ONERR` 줄로 갑니다. 디스크 읽기 오류는 I/O ERROR입니다. 글은 첫 `$00` 바이트에서 끝납니다. DOS는 텍스트 파일의 마지막 섹터를 `$00`으로 채우기 때문입니다.


### 메모리에서 찍기

글은 `$00` 바이트에서 끝납니다. `$0D`는 줄바꿈(캐리지 리턴)으로 찍힙니다. 이 방법은 디스크를 전혀 쓰지 않습니다.


## 멈추기

찍는 도중 **Ctrl-C**를 누르면 그 바이트를 그린 뒤에 찍기를 멈추고, 키를 가져가 호출한 곳으로, 즉 다음 BASIC 문장으로 돌아갑니다. `STORYT` 같은 BASIC 반복문에서는 Ctrl-C가 지금 찍는 파일만 끝내고, 반복문은 다음 파일로 계속 갑니다. 프로그램 전체를 멈추려면 Ctrl-Reset을 쓰세요. 이전에는 찍는 동안 Ctrl-C가 무시되어 키보드 버퍼에 남았고, 다음 `FILE NAME` 질문이 그것을 파일 이름으로 받아서 `ERROR #6`이 나왔습니다. **Ctrl-S**는 멈춥니다(아무 키나 누르면 계속합니다. 드라이버 자체의 멈춤입니다). **Ctrl-Reset**은 빠져나갑니다(`HAN`을 치면 드라이버가 다시 켜집니다). 검사에는 바이트마다 약 10사이클이 듭니다(바이트 하나를 그리는 데는 약 7,000사이클).

| 디스크 파일 | `TYPE`(바이너리, 종류 B) |


## 올라올 때 하는 일

`BRUN TYPE`은 파일을 올리고 `$8E00`에서 시작합니다. 시작 코드는 다음을 합니다.

1. `&`가 이미 TYPE에 의해 설치되어 있으면 아무것도 하지 않습니다. DOS가 이 프로그램이 쓰인 DOS 3.3이 아니면 역시 아무것도 하지 않습니다(DOS 오류 루틴 `$A6D2`의 첫 바이트를 확인합니다).
2. `HIMEM`과 문자열 꼭대기를 `$8E00`으로 낮춥니다. 그래서 BASIC 문자열이 코드나 버퍼를 덮어쓰지 못합니다. 문자열 꼭대기가 이미 `$9300` 아래이면 `?OUT OF MEMORY`로 멈춥니다. 그러므로 `BRUN TYPE`은 프로그램 앞부분에서 하세요.
3. 애플소프트의 `&` 벡터인 `$03F5`에 자기 처리 루틴으로 가는 `JMP`를 씁니다. 이전 벡터는 따로 보관합니다.

`&TYPE`이 아닌 `&` 문장은 처리기가 이전 `&` 루틴에 넘기므로, 다른 `&` 라이브러리도 계속 작동합니다.


## 파일 찍기가 작동하는 법

- VTOC(트랙 17, 섹터 0)을 읽고, 카탈로그 섹터를 따라가며, 30자 이름을 항목마다 비교합니다.
- 파일의 트랙/섹터 목록을 따라가며 데이터 섹터를 하나씩 `$9300`에 읽고, 바이트를 `COUT`으로 찍습니다(최상위 비트를 지우고, `$0D`는 `$8D`로 보냅니다).
- 오류는 DOS 자체의 오류 루틴 `$A6D2`로 보냅니다. DOS는 실제 입력과 출력 훅을 `$AA53-$AA56`에 두므로, TYPE은 먼저 그것을 `$36-$39`로 복사합니다. 그렇지 않으면 오류 메시지가 DOS의 훅을 다시 거쳐 잘못된 오류 번호가 찍힙니다.


## 메모리와 충돌

- 코드와 데이터는 `$8E00-$9103`, 버퍼는 `$9200-$93FF`입니다. 모두 낮춘 `HIMEM`이 보호합니다. 드라이버의 자체 상태는 `$9400-$95FF`에 있습니다.
- 영 페이지: `$06/$07`은 임시 포인터, `$50/$51`은 10진수 주소(롬 `GETADR`), `$5E/$5F`는 문자열(롬 `FRESTR`)에 씁니다.
- 글마다 시작하기 전에 드라이버의 조합 상태(한글 모드와 조합 중인 글자, `$94A7-$94AE`)를 지워서, 글이 깨끗하게 시작하도록 합니다.
- `$0300-$03CF`는 비워 두고, 언어 카드는 건드리지 않습니다.


## 속도

story 1부(3,767바이트)를 에뮬레이터 시간(초)으로 잰 값입니다.

| 방법 | 시간 |
|---|---:|
| 텍스트 파일을 BASIC `GET A$: PRINT A$;` 루프로 읽기 | 45.3 |
| `& TYPE,"NALGAE1"` | 24.6 |
| 메모리에 이미 있는 글, `& TYPE,"$8000"` | 19.7 |

시간의 대부분은 한글을 그리는 데 쓰입니다. 섹터를 직접 읽으면 디스크에는 약 5초만 들어갑니다.


## 한계

- 파일 이름은 DOS가 허용하는 30자입니다. `,D2`나 `,S6` 같은 뒷부분은 알아듣지 못합니다.
- `$00` 바이트가 들어 있는 텍스트 파일은 그 자리에서 일찍 끝납니다.
- DOS 3.3 텍스트 파일(종류 T)만 읽습니다. 바이너리와 애플소프트 파일은 `FILE TYPE MISMATCH`가 나옵니다.
